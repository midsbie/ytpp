* ytpp

Post-process YouTube downloads for TV compatibility.

Older smart TVs (e.g. LG C8) can't decode AV1 video or Opus audio, the codecs that YouTube increasingly defaults to.  =ytpp= re-encodes these streams to H.265/AC3 while copying anything already compatible, so videos play without hassle.

This repository also ships =ytdl= (a =yt-dlp= wrapper) and =ytcks= (a cookie extractor) to round out the download workflow.

** Quick start

1. /(Optional)/ Run [[*ytcks][ytcks]] to extract YouTube cookies from your browser into =cookies.txt=.
2. /(Optional)/ Run [[*ytdl][ytdl]] to download videos — or invoke =yt-dlp= directly if your config is already set up.
3. Run [[*ytpp][ytpp]] to transcode any files whose codecs your TV can't decode.

** ytpp

Re-encode incompatible video/audio streams (AV1, Opus) to H.265/AC3 while copying anything already compatible.

*** Usage

#+begin_example
ytpp [options] <file>
#+end_example

| Option              | Description                                                       |
|---------------------+-------------------------------------------------------------------|
| =-q, --quality <n>= | Quality level: QP for NVENC/VAAPI, CRF for software (default: 17) |
| =-f, --force=       | Force transcoding even if codecs are already compatible           |
| =--sw=              | Force software encoding (libx265)                                 |
| =--no-delete=       | Keep the original file after conversion                           |
| =-h, --help=        | Show help                                                         |

*** How it works

1. Probe the input for codec and dimension info.
2. Re-encode heuristics:
   - If AV1: re-encode video to H.265.
   - If Opus: re-encode audio to AC3 (Dolby Digital).
   - Otherwise: streams are considered compatible and copied as-is.
3. Video encoder is selected automatically: NVENC > VAAPI > software (via libx265).  Use =--sw= to force software encoding.

**** NVENC

When an NVIDIA GPU is available, =ytpp= uses =hevc_nvenc= with preset =p7= (highest quality), =hq= tune, B-frame references, spatial AQ, and 10-bit output.

**** VAAPI (Mesa radeonsi caveats)

VAAPI is used as a fallback when no NVIDIA GPU is available.  The Mesa radeonsi driver appears to have issues with HEVC encoding:

1. AMD VCN seems to require surface heights aligned to 32 (or 64×16 depending on generation).  Non-aligned heights (e.g. 1080) may be padded to the next aligned value (1088), filling extra rows with uninitialized data that **shows up as a green or noise bar**.  =ytpp= works around this by scaling *up* to the aligned height in software, uploading to VAAPI, then scaling back *down* with =scale_vaapi=.  Already-aligned heights (720p, 2160p) skip the extra scaling.

   This appears to involve Mesa, libva, and FFmpeg, as radeonsi may have historically reported incorrect block sizes, and FFmpeg defaulted to 16×16 alignment.  An upstream FFmpeg [[https://www.mail-archive.com/ffmpeg-devel@ffmpeg.org/msg161546.html][patch]] (Mar 2024) adds =VASurfaceAttribAlignmentSize= support, requiring libva ≥ 1.21.0.

   - [[https://gitlab.freedesktop.org/mesa/mesa/-/issues/9196][Mesa #9196]] :: Incorrect HEVC block size reported with radeonsi
   - [[https://gitlab.freedesktop.org/mesa/mesa/-/issues/9185][Mesa #9185]] :: Encoded files include padding at bottom/right (HEVC, AV1)
   - [[https://gitlab.freedesktop.org/mesa/mesa/-/issues/4559][Mesa #4559]] :: hevc_vaapi: wrong image width (48 px black bar)
   - [[https://bugs-devel.debian.org/cgi-bin/bugreport.cgi?bug=1081512][Debian #1081512]] :: hevc_vaapi produces 1920×1088 with green bar on AMD (Sep 2024)
   - [[https://github.com/obsproject/obs-studio/pull/11998][OBS Studio #11998]] :: Fix incorrect HEVC vertical resolution on AMD VCN (Apr 2025)
   - [[https://github.com/GPUOpen-LibrariesAndSDKs/AMF/issues/423][AMF #423]] :: AMD acknowledges alignment as a VCN4 limitation (Oct 2023)
   - [[https://github.com/LizardByte/Sunshine/issues/4314][Sunshine #4314]] :: Green line / black bars with HEVC on AMD (Sep 2025)

2. The encoder may produce malformed frames at unpredictable points, which can manifest on TVs as audio stuttering and resync pauses (possibly the hardware decoder stalling on a bad frame); in VLC it may show as visual corruption.

   - [[https://gitlab.freedesktop.org/mesa/mesa/-/issues/9436][Mesa #9436]] :: VCN2: broken H.264 video, HEVC encoder crashes
   - [[https://gitlab.freedesktop.org/mesa/mesa/-/issues/11730][Mesa #11730]] :: Tearing in all videos encoded via VAAPI
   - [[https://bugs.freedesktop.org/show_bug.cgi?id=109538][fd.o #109538]] :: Unstable HEVC encoding, garbled output (Feb 2019)
   - [[https://bugs.freedesktop.org/show_bug.cgi?id=110673][fd.o #110673]] :: HEVC encoding: segfault and garbled contents (May 2019)

NVENC appeared to avoid both issues in limited testing.

**** Software (libx265)

The software path uses 10-bit encoding (=yuv420p10le=) with =aq-mode=3= to redistribute bits toward dark scenes and reduce banding.

** ytdl

A convenience wrapper around =yt-dlp= for downloading.

*** Usage

#+begin_example
ytdl [--cookies <path>] [--skip-checks] <yt-dlp args>
#+end_example

| Option             | Description                                                          |
|--------------------+----------------------------------------------------------------------|
| =--cookies <path>= | Use a specific cookies file (default: =cookies.txt= in current dir)  |
| =--skip-checks=    | Bypass the yt-dlp config validation (see [[*Required yt-dlp config][Required yt-dlp config]]) |

=ytdl= passes =--cookies cookies.txt= automatically when that file exists in the working directory.  See [[*ytcks][ytcks]] for extracting cookies from your browser.

All remaining arguments are forwarded to =yt-dlp= unchanged.  The subsections below cover yt-dlp setup that =ytdl= benefits from but that applies to direct =yt-dlp= usage as well.

*** Output naming

Unless you set your own =-o/--output= (in the yt-dlp config or on the CLI), =ytdl= supplies a default template that numbers playlist items:

#+begin_example
%(playlist_index&{} - |)s%(title)s [%(id)s].%(ext)s
#+end_example

yt-dlp fills =playlist_index= only for items that belong to a playlist, channels and auto-generated mixes included, and leaves it empty otherwise. The one template covers every case:

- Playlist item :: =07 - Episode Seven [abc123].webm= (the index is zero-padded to the playlist's length, so files sort correctly).
- Standalone video :: =Some Video [xyz789].webm=, identical to yt-dlp's own default.

Because the choice is made per item, mixing a playlist and a lone video in a single command numbers only the playlist items.  Files are written flat in the current directory, so [[*ytpp][ytpp]] can transcode them in place.

If you set =-o= yourself, =ytdl= leaves it untouched.

*** PO Token (POT) provider

YouTube's bot detection may block downloads even with valid cookies.  When this happens, yt-dlp likely needs a Proof of Origin (PO) token provider plugin.

1. Install the [[https://github.com/Brainicism/bgutil-ytdlp-pot-provider][bgutil-ytdlp-pot-provider]] plugin by extracting the latest release ZIP under =~/.config/yt-dlp/plugins/=:

   #+begin_example
   ~/.config/yt-dlp/plugins/
   └── bgutil-ytdlp-pot-provider/
       └── yt_dlp_plugins/
           └── extractor/
               ├── getpot_bgutil_http.py
               ├── getpot_bgutil.py
               └── getpot_bgutil_script.py
   #+end_example

2. Start the POT provider container:

   #+begin_example
   docker run --name bgutil-provider -d -p 4416:4416 --init brainicism/bgutil-ytdlp-pot-provider
   #+end_example

3. Add =--js-runtimes node= to your yt-dlp config so the plugin's JS evaluation uses Node.js.

*** Required yt-dlp config

=ytdl= delegates format selection, player client choice, and JS runtime to your [[https://github.com/yt-dlp/yt-dlp#configuration][yt-dlp config]] (or CLI flags), so each user can pick what fits their media system without editing =ytdl=:

#+begin_example
-4
--mark-watched
-f "bv*+ba/b"
--extractor-args "youtube:player_client=tv,mweb;lang=en"
--js-runtimes node
#+end_example

| Flag                 | Why                                                                                 |
|----------------------+-------------------------------------------------------------------------------------|
| =-4=                 | Avoids IPv6-related 403 errors on reconnect                                         |
| =--mark-watched=     | Marks videos as watched on YouTube after downloading (requires cookies)             |
| =-f=                 | Format selector; pick streams your TV decodes natively (e.g. =315+140= for VP9+AAC) |
| =--extractor-args=   | Pins player client order; =mweb= pairs with PO tokens                               |
| =--js-runtimes node= | POT plugin requires a JS runtime                                                    |

=ytdl= errors if =--extractor-args= or =--js-runtimes= is missing from both the config file and CLI args, and warns if =-f= is missing.

Pass =--skip-checks= to bypass these checks.  Useful if your yt-dlp config lives outside the default path (=ytdl= only inspects =$XDG_CONFIG_HOME/yt-dlp/config=) or if you're intentionally downloading from a site where POT setup isn't relevant.

*** Recommended yt-dlp config

The flags in the table below aren't checked by =ytdl=, but make downloads more resilient on flaky networks or when YouTube throttles bandwidth.  Add them to your yt-dlp config alongside the required flags above.

| Flag                     | Why                                                                                   |
|--------------------------+---------------------------------------------------------------------------------------|
| =--retries 50=           | Retry the whole download up to 50 times on transient failures                         |
| =--retry-sleep exp=1:15= | Exponential backoff between retries, starting at 1s and capped at 15s                 |
| =--fragment-retries 50=  | Retry individual HLS/DASH fragments up to 50 times before giving up on the whole file |
| =--throttled-rate 100K=  | Restart the download if YouTube throttles the connection below 100 KB/s               |

*** Example yt-dlp config
#+begin_example
-4
-v
--mark-watched
--extractor-args "youtube:player_client=tv,mweb;lang=en"
-f "bv*[vcodec!^=av01]+ba[acodec!=opus]/bv*+ba/b"
--js-runtimes node
--retries 50
--retry-sleep exp=1:15
--fragment-retries 50
--throttled-rate 100K
#+end_example

** ytcks

Extract YouTube cookies from your browser into a =cookies.txt= file usable by =yt-dlp= (and [[*ytdl][ytdl]]).

*** Usage

#+begin_example
ytcks [--cookies <path>] [browser]
#+end_example

| Option             | Description                                                          |
|--------------------+----------------------------------------------------------------------|
| =--cookies <path>= | Write to a specific path (default: =cookies.txt= in current dir)     |

Without a browser argument, =ytcks= tries to detect the default browser via =xdg-settings=.  Supported values are =firefox=, =chrome=, =chromium=, and =brave=.  Firefox users with multiple profiles may need to specify the profile path explicitly:

#+begin_example
ytcks "firefox:~/.mozilla/firefox/xxxxxxxx.profile-name"
#+end_example

The output file is written with =chmod 600=.  By default both =ytcks= and =ytdl= read/write =cookies.txt= in the current directory, so no flag is needed when running them side by side:

#+begin_example
ytcks --cookies ~/cookies.txt firefox
ytdl --cookies ~/cookies.txt <yt-dlp args>
#+end_example

** Dependencies

- =ffmpeg= / =ffprobe=
- =yt-dlp= (for =ytdl= and =ytcks=)
- =node= (for the POT provider plugin's JS evaluation)
